Why Bruno, not Postman, for FHIR work

The API client is a governance decision, not a preference. When the collection is part of the deliverable, the defaults matter.

 BrunoPostman
Collection ✓.bru files in git — reviewed in pull requests, line-diffable –Cloud workspace, or a noisy JSON export that barely diffs
Network ✓Offline-first — no account, nothing syncs off the machine –Cloud sync on by default; account to do much
Audit ✓Open source — a security team can read exactly what it does –Proprietary; usage telemetry you have to vet
CI ✓bru run is free and unlimited on every commit –Automation gated behind paid seats
$ bru run . --env hapi-sandbox  → 8 requests, 8 passed Prohori — FHIR-native case registry, built in the open
